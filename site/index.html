ZollyBot

Governed agent offices for your repositories, with Jarvis running entirely on your phone. Agents run on your machine; you work them from any device.

Install on Linux

curl -fsSL https://raw.githubusercontent.com/khanshifaul/zollybot/main/site/install.sh | sh

Installs two binaries into ~/.local/bin, verified against the release checksum:

  • zollybot — the desktop app (AppImage).
  • zollybot-cli — the terminal companion.

Then add the directory to your PATH if it is not there already, and run:

zollybot

Jarvis, on the phone

Jarvis is the local assistant in the Android app. Download a GGUF model, then talk to it without sending the prompt to a server. The model, conversation history, and voice stay on the phone.

  • Download models from Hugging Face with pause, resume, size, and checksum verification.
  • Chat offline with spoken replies and a persistent conversation sidebar.
  • Use screen text as context, and set timers, open apps, dial, or open settings after confirmation.
  • Cloud fallback is opt-in. Local Jarvis never silently hands your prompt to a cloud agent.

First run

  1. Start zollybot and complete onboarding.
  2. Create an office from the app and choose the repository it works in. Each office keeps its own agents, memory, tasks and conversation history.
  3. Add agents, or let the Office Manager staff the office. The desktop app, terminal, and phone are views on the same running server.

Usage

Terminal UI

zollybot-cli

The terminal frontend attaches to a running ZollyBot server and shows the same agents and conversations as the desktop app. It does not edit an office directly.

Scripts and SSH

zollybot-cli agents
zollybot-cli brief --office <office-id>

agents prints the agents the app lists. brief prints the selected office's memory facts; omit --office to list the offices first.

Gates and memory

Money, production, publishing and customers always stop for you. Code reaches the main branch only through the reviewer step. The app cannot skip either — the block lives in the backend, not in a prompt. Each office remembers its own decisions and lessons, written atomically and never by the UI directly.

How it fits together

  • An office is a repository, not a machine. Every device is a view on the server that owns the office.
  • Local first. Agents and files stay on the machine that owns the repository; remote devices are controls, not workers. Android Jarvis runs its model on the phone.
  • One release source. The installer, updater, and download page all read the same GitHub release manifest.
